# Архитектура

```
браузер ──HTTPS──▶ обратный прокси (Caddy) ──▶ web (Next.js, /api/v1 → прокси) ──▶ api (FastAPI)
                                                                                    │
                     ┌──────────────── PostgreSQL ◀──────────────────────────────────┤
                     │  реестр, портреты (JSONB), журнал обращений, аудит,            │ arq
                     │  санкционные списки (pg_trgm)                                  ▼
                     │                                                 Redis ─▶ worker
                     │                                                            │  │  │
                     └──────────────────────────────────────────────────────────┘  │  │
                                                   SearXNG (метапоиск) ◀───────────┘  │
                                                   Ollama (qwen3) ◀───────────────────┘
                                                   сайты-источники, списки ООН/OFAC/ЕС/UK (интернет)
```

## Компоненты

| Сервис | Назначение | Наружу |
|---|---|---|
| `web` | Next.js 16 (standalone): интерфейс ru/kk/en, прокси `/api/v1/*` на API с передачей cookie и CSRF | 127.0.0.1:3000 → прокси |
| `api` | FastAPI: вход, реестр, портреты, решения, экспорт, обмен, администрирование, `/healthz`, `/readyz`, `/metrics` | нет |
| `worker` | arq: построение портретов, ежедневное обновление санкционных списков, очистка сессий | нет |
| `migrate` | `ipdl db upgrade` перед стартом API и воркера | — |
| `postgres` | PostgreSQL 17 + pg_trgm | нет |
| `redis` | очередь задач (без персистентности: состояние задач — в PostgreSQL) | нет |
| `searxng` | собственный экземпляр SearXNG, JSON API, без лимитера | нет |
| `ollama` | локальная LLM (данные о лицах не уходят во внешние сервисы) | нет |

## Пайплайн портрета (`src/ipdl/analysis/pipeline.py`)

1. **Поиск** — 17 шаблонов запросов (`methodology/search-queries.yaml`) по вариантам имени
   (кириллица, «Имя Фамилия» без отчества, латиница); ссылки дедуплицируются, без упоминания
   лица — отбрасываются, ранжирование: упоминание в заголовке, число запросов и поисковиков,
   тип источника (официальный > справочный > СМИ).
2. **Загрузка** — до 16 страниц: проверка адреса (только публичные IP), robots.txt, ≤ 3 МБ,
   trafilatura/pypdfium2; модели передаются только абзацы с упоминанием лица (≤ 3 500 знаков).
3. **Санкции** — имя (все варианты) по спискам в PostgreSQL: триграммный отбор + сравнение
   токенов, сверка даты рождения.
4. **Факты** — до 10 источников (чередуются биографические и «рисковые» темы, ≤ 2 с домена),
   на каждый один запрос к LLM со строгой JSON-схемой и проверкой цитат.
5. **Оценка** — сведение фактов (дубликаты на разных языках объединяются, расхождения
   показываются), статус ИПДЛ, скрининг связанных лиц и компаний, 8 факторов, заключение.

Каждый этап деградирует мягко и пишет предупреждение в портрет (поиск недоступен, модель не
ответила, списки устарели, перечни FATF старше 130 дней).

## Данные

* `persons` — карточка реестра + сводные поля текущей версии (для списка и фильтров).
* `portraits` — версия портрета = задача (статус, этап, прогресс) + результат `data` (JSONB,
  модель `ipdl.analysis.model.Portrait`) + решение аналитика `review` (JSONB). Действующий
  портрет = `data` с применённым `review`; автоматический результат не перезаписывается.
* `requests` — журнал обращений (входящие/исходящие запросы, передачи портретов партнёрам).
* `partners`, `users`, `sessions` (хэш токена), `audit_events` (только добавление).
* `sanctions_lists`, `sanctions_entries`, `sanctions_names` (скелеты имён + GIN pg_trgm).

## Роли

| Роль | Права |
|---|---|
| admin | всё, включая пользователей, партнёров, удаление записей, обновление списков, журнал действий |
| analyst | проверки, решения, экспорт, запросы и передачи партнёрам |
| viewer | просмотр реестра, портретов, санкций, методики; экспорт |
| partner | только портреты, переданные его ПФР (именно переданные версии); экспорт; запрос доп. информации |

## Масштабирование

Узкое место — LLM: на CPU (48 ядер) qwen3:4b тратит ~20–50 с на источник, портрет — 3–4 мин.
`IPDL_JOBS__MAX_CONCURRENCY` и число воркеров (`docker compose up --scale worker=N`) задают
параллельность; на GPU — `docker compose` с драйвером NVIDIA для ollama и модель `qwen3:8b`+.
API без состояния — масштабируется горизонтально.
